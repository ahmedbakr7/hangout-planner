### Minor (fix with the rebuild; not blocking on their own)

- **M1. `src/server/db/test-schema.test.ts:53-63`: the AC-2 test cannot detect a data change.**
  - Rule: kit rule 6 ("Tests prove behaviour"), and review step 2 ("would this test fail if the behaviour broke?").
  - The AC says the call "changes nothing", but the test compares only table names and the return value. An implementation that truncates or drops and recreates the tables, then returns `false`, still passes. I checked this by mutation.
  - Change wanted: before the call, insert a row (for example into `accounts` in the test schema) and assert it is still there afterwards. Or compare a catalog fingerprint: columns, constraints and the `pg_type` enum.
- **M2. `vitest.config.ts:7`: no automated test fails if `globalSetup` is removed from the unit config.**
  - `e2e/test-schema.e2e.ts` imports `setup()` directly, so it proves the function, not the wiring that fixes the ticket's race.
  - I checked the wiring by hand. On fresh databases the full unit suite passed 3 of 3 runs with the wiring (360 tests). With the `globalSetup` line removed, it failed 3 of 3 runs (1 file failed, 11 tests skipped).
  - This is not an AC, so it does not block. Optional change: have the integration test assert that both configs list `./vitest.global-setup.ts` by loading the config objects. Do not assert on the source text.
