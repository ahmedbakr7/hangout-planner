## Findings

### Blocking

**B1. `src/components/create-form.tsx:313`: a revert of the currencies path to `/v1/currencies` passes every test.**
- Rules broken: AGENTS.md rule 6 (each AC's test must fail if the behaviour breaks). AC-1 covers every request. The ticket body says "a test that stubs fetch by URL must fail if a component calls an old `/v1/` path".
- Why it survives: `loadCurrencies` swallows a failed or thrown fetch and keeps `DEFAULT_CURRENCIES` (`create-form.tsx:35`, `:301`). That default is identical to the stub's `currenciesBody` (`create-form.test.tsx:44`). `create-form.test.tsx:268-275` therefore cannot tell whether the request was made or where it went. `e2e/rtl.e2e.ts:119` stubs the path but asserts nothing about it, and `e2e/ui-api-paths.e2e.ts` never renders `CreateForm`.
- Wanted: a `T-001-32/AC-1` test that fails on this mutation. For example: assert that the fetch mock received `GET /api/v1/currencies`. Or have the stub return a list that differs from the defaults (such as a subset) and assert the select shows it. Or render `CreateForm` in `e2e/ui-api-paths.e2e.ts` and assert that `GET /api/v1/currencies` was requested and `unserved` is empty.

**B2. `src/components/join-panel.tsx:418`: a revert of the Retry path's `GET /api/v1/me` to `/v1/me` passes every test.**
- Rules broken: same as B1.
- Why it survives: `loadOpening` (`join-panel.tsx:410-418`), which the Retry buttons at `:632` and `:657` call, has its own `fetch("/api/v1/me")`, separate from the effect at `:471`. No test clicks Retry and then asserts the outcome. `join-panel.test.tsx:345` only checks the Retry button's classes.
- Wanted: a `T-001-32/AC-1` test that loads the panel, makes the first opening request fail, clicks Retry, and asserts the reloaded preview and signed-in state. The stub answers only `/api/v1/...`, so the old path would fail. Better still, make `loadOpening` the single loader and have the effect call it. That removes the duplicated fetch pair at `:416-419` / `:469-472` that let this path go untested (rule 5).

### Minor (non-blocking)

**M1. Evidence maps AC-1 onto tests that miss about half of the paths.** The AC-1-tagged tests detect only 11 of the 21 reverts. The other 8 that are caught fail only untagged tests:
- `account-gate.tsx:178`, `:243` (accounts branch)
- `invite-panel.tsx:439`, `:478`, `:548`, `:751`
- `join-panel.tsx:403`, `:407`

`invite-panel.test.tsx:659` exercises only `InvitationsList`, not the organizer `InvitePanel` (`GET .../invite`, `POST .../invitations`).

Wanted: tag the tests that actually prove those paths `T-001-32/AC-1`, or add one tagged test per component that asserts the full set of requested `METHOD path` pairs. That keeps the evidence's AC-to-test mapping honest.

**M2. `e2e/ui-api-paths.e2e.ts` routes only `AccountGate`, `HomeList` and `InvitationsList` through real handlers.** `CreateForm`, `InvitePanel` and `JoinPanel` (12 of the 21 path literals) never reach a real route. `sdlc.toml` names integration as this product's `real_stack`. Wanted: render those three as well, with a plan created through `POST /api/v1/plans` for the invite and join panels, and assert `unserved` is empty. That would also close B1.

**M3. `e2e/ui-api-paths.e2e.ts:136-139` depends on test order.** It relies on module-level `cookieJar` state left by the previous test, with a fallback `register()`. Wanted: reset `cookieJar` in `beforeEach` and register explicitly in each test that needs a session.
