Next.js 15.x reaches end of life on 2026-10-21; main runs 15.5.27. Move to 16.4.0, the current stable. The lead installs `next@16.4.0` before the build starts (agents cannot run `npm install`), so the installed package is already 16.4.0: change `package.json` to `"next": "^16.4.0"` and make the code pass under it.

Next 16's `next build` type-checks `tsconfig.json`, which includes the tests, and fails on the 9 known test type errors (the `typecheck` baseline; roadmap item 2). Fix each in its test file without changing what the test asserts: `shell-tokens.test.ts:108` (regex flag needs es2018), `join-panel.test.tsx:138` (duplicate `error` key), `client.test.ts:145-146` (`.ts` import path; `dbCredentials` on the drizzle-kit `Config` type), `schema.test.ts:141,145,149` (an enum passed where a table is expected), `views.test.ts:300` (`kind` widened to `string`), `attempt.test.ts:700` (`instanceof` on a non-object type). Then prune the `typecheck` baseline entry with `sdlc baseline --prune` and read the result before committing it.

Apply the two `tsconfig.json` changes Next 16 makes on its first build: `"jsx": "react-jsx"`, and `.next/dev/types/**/*.ts` added to `include`. No other config change. The code already awaits `params`, `searchParams` and `cookies()`, has no middleware, and sets no image, webpack or experimental options; if Next 16 still needs a code change, make the smallest one and name the Next 16 change it answers in the commit message. Do not adopt new Next 16 features (Cache Components, `proxy.ts`, React Compiler) in this ticket.

`src/next-version.test.ts` holds the AC-1 test (it reads the installed `next/package.json`) and the AC-2 test (it runs `tsc -p tsconfig.json --noEmit` and expects exit 0). `test: none`: there is no new behaviour to prove through the real stack; the build gate's full unit suite, `next build` and the smoke probes against `next start` are the proof that pages and route handlers still work on 16.
