# ADR-0016: Kit v5.5.0; test_files, prose-only lead PRs and declared binaries stay at their defaults

- Status: accepted
- Date: 2026-10-27
- Source: lead. On 2026-10-27 the lead approved the bump ("Go" on the list that named it).
- Supersedes: none
- Amends: ADR-0013 § Decision, the line "Pin the kit at v5.1.0". The rest of ADR-0013 stands.

## Context

The pin is v5.1.0 (`078ca93`). The kit released four MINOR versions and one PATCH since, all on 2026-10-24 to 2026-10-26 (kit `CHANGELOG.md`). None says an upgrade needs a change:

- v5.2.0: `sdlc plan <ticket>` shows a ticket's lane, checks, write sets and owed proof before a build. `sdlc lint` warns when a build is certain to fail.
- v5.2.1: `gate ci` names the remedy for a done ticket without real-stack proof: a `type: test` ticket with both tags, or a lead waiver. The Hangout pilot reported this (roadmap item 6).
- v5.3.0: a ticket's `test_files` lists paths outside production source that its test play may also write, such as a fixture or a shared test helper (kit ADR-0007).
- v5.4.0: `[scope] lead_light` lets a lead PR that changes only prose take one approval instead of two (kit ADR-0008). It is empty by default.
- v5.5.0: `assets.toml` declares binary files with a sha256 and a generator or pinned source. A new `assets` check reports undeclared or changed binaries. It warns and passes until `[assets] mode = "fail"` (kit ADR-0009).

`sdlc doctor` passes under v5.5.0 with today's `sdlc.toml`. The default gate lists now include `assets`, and this product does not override them.

## Decision

- Pin the kit at v5.5.0 (`27c9f92`).
- `[scope] lead_light` stays empty. The only prose under `docs/` is the roadmap and the pilot report, and agents read the roadmap's "Running it" as instructions. Both keep the two-approval path.
- `[assets] mode` stays at the default (warn). No `assets.toml` yet. The only binaries are the font files in `src/app/fonts/` (T-001-74). A ticket that adds or changes a binary must declare it first, in a lead PR. Moving to `fail` is a separate lead decision.
- `test_files` is available to new tickets. It is the convention for a test helper shared by more than one test file (roadmap items 10 and 24), so long as the ticket lists it.

## Consequences

- A branch that adds or changes a binary gets an `assets` warning in the build, test, PR and CI gates until it is declared.
- `sdlc plan <id>` joins the runbook's pre-build steps.
- `sdlc/approval` is judged by the kit pinned on the base branch, so this PR is judged by v5.1.0 and every PR after its merge by v5.5.0.
