# ADR-0001: Stack

- Status: accepted
- Date: 2026-09-25
- Source: intent/intent-001-core-plan-loop.md / design/spec-001-core-plan-loop.md
- Supersedes: none

Normative HTTP, tables, authz, and the proposal attempt are in `arch/CONTRACTS.md`. This ADR is the decision to adopt that contract and the stack below. A change needs ADR-0002 and a contract edit in the same change. Do not edit this file in place.

## Decision

One TypeScript app. Next.js (App Router) on Node 22 serves Arabic and English pages and a JSON API on the same origin. PostgreSQL 16 stores the plan. Drizzle is the only query layer. The browser never calls Google and never sees an API key or a starting coordinate.

### Web

- Next.js App Router, React, TypeScript strict. Locale is the `hp_locale` cookie (`ar` or `en`), not a path segment, so a share link stays stable and a language switch does not remount a form.
- Chrome strings live in `messages/en.json` and `messages/ar.json` via next-intl. A missing Arabic key renders the English string and keeps `dir="rtl"`.
- Direction comes from the locale. Layout uses logical CSS properties. Faces: IBM Plex Sans Arabic and IBM Plex Sans. Token values are in `design/DESIGN.md` and may appear as hex only in `src/app/tokens.css`.
- No component library and no utility framework with its own spacing scale.

### API

- JSON over HTTP at `/v1`, implemented as Route Handlers. Cookie session, same origin, no CORS.
- Mutations require header `X-HP-Request: 1`.
- One error envelope, defined in `arch/CONTRACTS.md`.
- Page loads call the same view functions as the route handlers. Server Components are not a second API and do not add fields.

### Data

- PostgreSQL 16. Connection string `DATABASE_URL`.
- Drizzle ORM and SQL migrations in `drizzle/`. This slice ships `drizzle/0001_init.sql`. No down migration.
- Money is an integer minor-unit amount plus an ISO 4217 code. No floats and no exchange rates.
- v1 currency list: EGP (exponent 2, default on the create form), USD, SAR, AED (all exponent 2). Another currency is a new row in that list and a contract edit, using the same budget and price layout.
- Plan timezone is an IANA name. Windows are a civil date plus local start and end times in that zone. The product shows those wall times and the zone name. It does not convert into the viewer's zone.
- Plan state is a column: `collecting`, `blocked`, `proposed`, `locked`.

### Account

- Organizers and optional invitee accounts are email plus password. Password hashing is argon2id in one helper. The session cookie is `hp_session` (httpOnly, SameSite=Lax, 30-day sliding expiry). The cookie stores a random token; the database stores its SHA-256.
- Display name is required at registration, 1–40 characters after trim, and is the name shown for that account. Email is the login and is returned only from `GET /v1/me` and the account's own session responses.
- There is no OAuth, passkey, profile edit, outbound email, or SMS in this slice.
- In-app invite identifier is that account email, exact match after trim and lowercase. The invite surface has a single field. Identification failure adds no row (`arch/CONTRACTS.md`).
- Anonymous join creates a participant and a `hp_guest` session cookie. The same browser session keeps that participant. Another browser is another participant, including when the display name matches. No password on that path.
- A resolved share link records a `hp_link` grant for read of that plan's preview and, once locked, the confirmed outing. The grant is not a participant and cannot edit, swap, or lock.
- Shared display names get a stable 4-character distinguisher from `abcdefghjkmnpqrstuvwxyz23456789`, unique on the plan. It is not an email, a phone number, or a starting point. Lists return it; the UI shows it when that list contains another row with the same display name.

### Google

Server-side only, API key `GOOGLE_MAPS_API_KEY`.

- Venue search, venue price, and the approximate start search use Places API (New): `places:searchText` and Place Details. The per-person amount is `priceRange.startPrice` when its currency is the plan currency. `priceLevel` does not qualify. Amounts in another currency do not qualify. There is no level-to-money table.
- Travel time uses Routes API `computeRouteMatrix`, `travelMode: DRIVE`, `routingPreference: TRAFFIC_UNAWARE`, waypoints as lat/lng. Field mask `originIndex,destinationIndex,status,condition,duration`.
- Start search is Places text search. The participant confirms a result. The server stores the place id, the returned name, and coordinates. Coordinates are not on any API response.
- Ranking, the median-travel warning, and swap snapshots are the proposal-attempt section of `arch/CONTRACTS.md`. Unfairness warns and does not block lock. Cost is outside the comparison.

### Caps

Title 80, step name 60, option label 40, display name 40, after trim. Password 8–72 characters, not trimmed. Windows 1–7 per plan, each with end after start on that civil date. Steps 1–6, options 2–4. Threshold 1–100. Participants per plan 100, because one route-matrix request must stay within 625 elements (cohort origins × up to 5 first-place candidates). Join past that cap fails and changes nothing.

### Screens

Cookie locale, paths in `arch/CONTRACTS.md` § Screens. The copied link is `/join/{token}` for the life of the plan.

## Consequences

- One deployable Node process and one database. The session cookie needs no cross-site setup.
- A Places result that only has `priceLevel`, or a price in another currency, is dropped. In Egypt that can block a proposal until a venue has an EGP `priceRange`. The budget-blocked state is that outcome. The product does not invent a price.
- `priceRange.startPrice` is the amount compared with the budget, so a range that starts under the budget and ends over it still passes.
- Invite-by-email tells the organizer whether that email is registered. That is the identification failure the spec already requires.
- Answered count equals the number of participants whose current response is complete. A complete response is replaced only by another complete valid response, so the count and the answered status stay the same number. The first time a participant becomes complete, the count increases by one and does not increase again.
- Windows do not cross midnight. A later night is a second dated window.
- Proposal attempts run inside the triggering request, after the triggering write commits, with a 20s budget. No queue and no public event.
- `HP_PROPOSAL_ENABLED=0` records a venue-data block and does not call Google.
- There is no unlock route. Lock is the confirmation.
- Visual values live in one CSS file. Components refer to token names.

## Not decided

- Which company hosts the Node process and PostgreSQL.
- Outbound email or push when an invitation row is created. The invitee sees the row on the invitations surface.
- OAuth, passkeys, and account recovery.
- Currency conversion, machine translation, per-viewer time zones, map images, and native apps.
- Link revoke and rotate.
- Windows that cross midnight.
